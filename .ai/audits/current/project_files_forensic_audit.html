Both owner-reported leads are confirmed

Each was established independently on three evidence streams — Figma node geometry, Flutter source, and on-device semantics bounds. Neither rests on a screenshot comparison.

Beyond those two, the dominant pattern is typography: the implementation is systematically smaller and heavier than the design. The AppType scale simply does not contain several sizes Figma uses (36, 22, 18-Medium), and because a guard test holds the inline fontSize/fontWeight ratchet at zero, none of it can be corrected at the call site — the scale itself has to change. The second pattern is accumulated vertical drift: individually small gap shortfalls compound down a column until a bottom element is over 100 dp out of place.

The news is not uniformly bad. Structure and child order matched Figma on every screen audited except the quiz. Colour discipline held completely — no hardcoded Color() was found outside the theme layer on any audited screen. The bottom navigation bar, including its raised centre notch and active indicator, matches the design. And the dark canvas’s lavender back-light — the elevation mechanism the project once could not even see in Figma — is genuinely built.

13 AI-agent traps

Each of these produced, or would have produced, a wrong conclusion during this audit. They are the most transferable output here — hand them to any agent that works this repo next.

Figma Glass is invisible to the MCP

A Glass surface inspects as a plain translucent rectangle. Node 337:15643 (onboardingSheetGlass, group G1) returned only bg-[rgba(35,38,40,0.2)] and a plain shadow — none of its frost/refraction/depth values.

Consequence: An agent that trusts the MCP will conclude “Figma has no Glass here” and build a flat surface. 20 Glass groups across 363+ nodes are affected. Treat DESIGN_ISSUES.md #72 as Figma truth for Glass.

A missing shadow is not evidence of no shadow

Node 349:16719 (nav bar_Dark) has a documented lavender back-light — rgba(124,58,237,0.1), blur 12.5. get_design_context returned no shadow at all: the whole background had been flattened into one SVG with negative insets.

Consequence: Absence in MCP output must be reported as UNVERIFIED, never as “the design does not specify it”.

The Figma file has no variables and no theme modes

search_design_system returns zero components and zero variables. A whole-screen get_variable_defs yielded two entries. libraries_added_to_file is empty.

Consequence: There is no token layer to diff against. Light and Dark are separate hand-drawn frames, so an agent must be handed each variant’s node id — it cannot switch a mode, and cannot find dark frames by searching “dark”.

Layer names carry invisible characters

The Mistakes family is named Learn(ٍMy Fault) for school student — with an Arabic kasratan inside the English word.

Consequence: Every search for the clean spelling silently returns nothing. Search short distinctive substrings, never full names.

Figma line-heights are fractional px; Flutter’s is a multiplier

Inter Bold 16px resolves to line-height 14.854 in Figma (its “auto” using font metrics). Flutter’s height is a multiple of fontSize.

Consequence: Naive comparison manufactures dozens of false typography findings. Figma “auto” maps to height: null, not to a computed number.

Cairo is bundled but can never render Latin text

Figma specifies Cairo for Latin runs in at least two places — quiz option letter badges (308:5206, Cairo Bold 11) and the Mistakes caption (404:6338, Cairo SemiBold 14). The app bundles Cairo, but app_theme.dart:53-54 sets fontFamily: 'Inter' with fontFamilyFallback: ['Tajawal','Cairo'].

Consequence: Latin glyphs always resolve to Inter, so the fallback chain can never produce Cairo. Already recorded as DESIGN_ISSUES #68, still open for the designer. The quiz badge is a new instance that extends #68’s table — it is not a new issue.

Many divergences are already decided

DESIGN_ISSUES.md carries ~48+ numbered entries, several of which authorise the current behaviour with a recorded reason (e.g. #68 Cairo, #75 illustration fit, #21/#22 dark Log In inversion).

Consequence: Filing an authorised divergence as a bug wastes the implementation session. Grep DESIGN_ISSUES / DECISIONS / KNOWN_BUGS before filing.

Deliberate-looking inconsistency can be intentional

Home renders its three “Coming soon” placeholders three different ways. This looked like a token slip; coming_soon_section.dart:22 defines enum ComingSoonSurface {dailyTasks, continueLearning, topStudent, plain}, each mapped to its own Figma surface.

Consequence: Checked and deliberately not filed. Read the widget before filing a visual inconsistency.

Viewport clipping looks like a layout bug

On Leaderboard the user’s own row measured 1.1 dp tall; on Profile the last row measured 35 dp.

Consequence: Both scroll and clear. Checked and deliberately not filed. Scroll before measuring the last row.

PowerShell redirection corrupts binary output

adb exec-out screencap -p > file.png under PowerShell prepends a BOM and produces an unreadable PNG.

Consequence: Use adb shell screencap -p /sdcard/x.png then adb pull.

Two devices attached silently breaks every adb call

The owner’s physical Pixel 8 connected mid-session alongside the emulator; every unqualified adb call failed with more than one device/emulator.

Consequence: Always pass -s emulator-5554. The physical device was never installed to or driven.

FLAG_SECURE blanks screenshots but not semantics

The quiz screen sets FLAG_SECURE, so screencap returns black.

Consequence: uiautomator dump still returns the full semantics tree with bounds — which is what the child-order and position findings rest on. No code was modified to work around it.

16 Is the app design-faithful?

On the evidence gathered: partially, with one structural defect and one systematic one. No score is offered, because the sample does not support one.

What the evidence does support, stated plainly:

  • Structure is sound. On four of the five screens examined closely, the Flutter widget hierarchy and child order follow the Figma document order exactly. The quiz is the single exception, and it is a real one.
  • Component construction is careful. Padding, radii, hairline widths and fills repeatedly matched Figma to the decimal — 20.5 dp padding, 41.9 vs 42 dp pill, 12 dp option gap. Where the build diverges it is usually documented in DESIGN_ISSUES.md with a reason.
  • Typography is systematically wrong, in one direction, for a structural reason — the scale is missing sizes the design uses — and it cannot be fixed without the designer.
  • Vertical rhythm drifts. Small gap shortfalls compound; login is over 135 dp out by the bottom of the screen.
  • Colour and theme discipline is the strongest area. No hardcoded colour outside the theme layer on any audited screen, and the dark back-light mechanism is genuinely implemented.

The honest limit: five screens of nineteen, one device size, one language for most measurements, and no independent verification of the 20 Glass groups. A confident verdict on the app as a whole is not available from this dataset, and this report does not offer one.
