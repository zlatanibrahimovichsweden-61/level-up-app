Executive summary

What the project is

A single Flutter app (Android + iOS target, iOS never built) for Egyptian students, forked at registration into School and University tracks. Phone-OTP login, a four-step registration wizard, a Home dashboard, a subject catalog (Learn), a multiple-choice quiz engine with server-awarded points, a profile/settings cluster, and — uncommitted — a leaderboard. The app is purchase-silent by contract (no paywall, price or checkout; purchases happen on the website) and many users are minors, which drives the storage, logging and backup rules.

Architecture in one breath

Feature-first Flutter. Riverpod 3 is both state and DI (no get_it); Bloc is confined to the quiz session by a guard test. GoRouter with a pure redirect function and a five-tab StatefulShellRoute. Dio with two interceptors (single-flight token refresh; typed AppException mapping). freezed/json_serializable models with committed codegen. A ThemeExtension palette and a designer-transcribed type scale, both held at zero exceptions by tests. Arabic-first localization with ARB parity enforced.

Major functionality that exists

  • Onboarding → phone login → OTP with the new/existing fork → registration (both tracks, contract v1.1 city/school escapes) → Home
  • Learn: subjects → school unit/chapter/lesson tree or university lectures with quiz-type tabs
  • Quiz: create → answer loop with AI explanation polling → finish → result, with weekly-limit sheets and screenshot protection
  • Profile hub, Edit Profile (PATCH /me, email tri-state), Settings (language, theme, rank privacy), four disabled account shells
  • Session hygiene: device-bound tokens in secure storage, forced logout on eviction, full session-scope invalidation on sign-out
  • Uncommitted: a complete-looking leaderboard tab (podium, scopes, infinite scroll) — built on a draft endpoint

Maturity and the biggest concerns

  • Maturity: seven weeks of dense, disciplined work; 890 green tests incl. 17 mechanised rules; every stable endpoint has client code. BUILD-verified, largely not DEVICE-verified (last physical walkthrough 2026-08-04, emulator run 2026-09-05).
  • Contract drift: the vendored contract is pinned at 184d6ec (3.0.0-m1, 09-03) while the partner's repository has moved 12 commits to 3.9.2-m1 (09-08). In that newer contract both leaderboard operations are stable (3.5.0-m1, 09-05), account deletion is stable (3.8.0-m1, 09-07), and — flagged in red by the partner — GET /questions/{id}/explanation is published stable but has no backend route. The leaderboard was built against the newer contract; the pin, contract/ and every record still describe the old one.
  • Silent failure paths: 10 fail-able providers lack retry:, so on a device a failed reference/avatar load may never show its error state; GET /me/entitlements never fires because nothing reads the provider.
  • Live API gap: staging answers 405 for PATCH /me, 404 for entitlements, and has no seed data for the test cohort — the quiz loop and the 3.0.0-m1 finish body have never been observed on the wire.
  • Release readiness: prod URL is a placeholder, no signing key, no account deletion, placeholder legal copy, template store identity, iOS never built.
  • Documentation weight: ~1.6 MB of Markdown across docs/ and .ai/ for 22k lines of hand-written Dart; several layers are stale or duplicated.

Project architecture

Entrypoints
main.dart → main_dev · main_staging · main_prod · main_mock (overrides dioProvider with a canned backend). The -t flag is the only flavor mechanism — no Gradle flavors, no iOS schemes.
▼
Bootstrap / Root
bootstrap(): AppConfig.init → PreferencesStore.load() before runApp → ProviderScope → LevelUpApp (MaterialApp.router, two themes, AR default, one status-bar style).
▼
Routing
One GoRouter; pure authRedirect(AuthStatus, location); pre-auth / /login /otp /register/**; StatefulShellRoute ×5 (home · leaderboard · learn/** · message · account); full-screen routes outside the shell (quiz, profile/edit, settings, shells, legal).
▼
Presentation
12 feature folders, each {models, notifier, repository, screens, widgets}; shared core/widgets (StateWidget, OfflineBanner, CircleBackButton, LanguagePill, TitledChrome, form fields); a hand-painted notched nav bar.
▼
State
Riverpod: 5 Notifier · 10 AsyncNotifier · 8 FutureProvider · 1 StreamProvider · ~12 DI Providers. Bloc: QuizBloc only (guard-enforced). AuthController is the single auth truth; invalidateSessionScope() is the session inventory. AsyncValue → sealed ScreenState → StateWidget.
▼
Data
Six repositories (+ leaderboard, untracked) — the only code that touches Dio; freezed/json_serializable models, camelCase wire, committed codegen; hand-written serializers where freezed's envelope is wrong (city union, email tri-state, auth result); CursorPage<T> pagination.
▼
Network
dioProvider [AuthInterceptor: Bearer, 401 → single-flight refresh on a bare client → retry once → forceLogout] [ErrorInterceptor: DioException → sealed AppException]; isOnlineProvider from connectivity_plus.
▼
Storage
SecureStorage (tokens + device_id; iOS first_unlock_this_device, no iCloud sync) · PreferencesStore (theme, locale) · memory only for everything else — no offline cache.
▼
Backend
Vendored OpenAPI 3.0.0-m1 (21 stable · 15 draft). Staging on Railway (13/21 stable verified); prod TBD.example; SignalR hubs not drafted.

Shared components and the design system

  • Colour: AppColors ThemeExtension, ~60 tokens per palette, each annotated with its Figma node; palette guard holds zero exceptions across 38k lines.
  • Type: AppType — 18 designer styles on 28→24→20→18→16→14→12→10 (+11 nav), bridged to Material's TextTheme; typography guard at zero.
  • Surfaces: one dialog system (dialogTheme/datePickerTheme pinned to cardFill, no surface tint).
  • Screen states: sealed ScreenState + StateWidget, used by catalog, profile, edit-profile, settings, leaderboard — not by Home.
  • Chrome: CircleBackButton, TitledChrome, LanguagePill, OfflineBanner — one copy each, after Day 7b removed duplicates.

Architectural observations (from the code, not the docs)

  • lib/core/ imports lib/features/auth/ (Dio needs AuthController) — an acknowledged, annotated provider cycle.
  • Track, the glossary's first term, lives in profile/models/ and is imported by six features; CursorPage lives in registration/models/ and is reused by the leaderboard. Two accidental shared kernels.
  • settings/ is a profile screen in its own folder; shell/ and account_shells/ use "shell" in two unrelated senses.
  • Two features are empty scaffolding (subscription, track: eight .gitkeep directories) and one route (/track-select) is unreachable.
  • units_screen.dart and lectures_screen.dart contain views, not screens; neither is routed, which reads as dead code until you follow the import.

Overall verdict
🟡 Fair / Functional but Incomplete

Why not higher. The app cannot ship: the production backend does not exist in the contract, the release artefact is unsigned, both stores' mandatory account-deletion and privacy-policy requirements are unmet, iOS has never compiled, and no physical device has run the current tree. Only 13 of 21 stable operations have ever decoded a real response; the quiz loop — the product — is unverified on the wire. Home is four stubs around a header. The vendored contract is nine versions behind the partner's, the in-flight feature was built past that pin without moving it, the AI-explanation surface models a route that does not exist, and ten providers can fail silently on a device. Feature completion and API integration sit at Fair; production readiness is Needs Work.

Why not lower. Everything that is built is built carefully: a clean layered architecture with typed error boundaries, a sealed screen-state model, single-flight token refresh proven under concurrency, session hygiene for shared devices, zero hardcoded colours or sizes across 38k lines, Arabic-first localization with enforced parity, 890 green tests including 17 mechanised rules that are themselves tested and proven to fail, committed codegen with CI drift checks, an unusually honest decision/risk/design-gap record, and every stable endpoint already wired. The two CRITICALs of the August audit (release networking, cross-student data leak) were fixed and proven at ARTEFACT level. Nothing found here is a rewrite; the defects are local.

Net. As an engineering codebase this is Good to Very Good. As a project — a product that has to reach a store — it is functional but incomplete, with most of the distance to "Good" owned by the backend partner, the designer and legal rather than by the Flutter code. The marker sits at the upper edge of Fair for that reason.
